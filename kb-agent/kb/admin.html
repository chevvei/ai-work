项目开关

启用：关闭后该项目的资料完全不参与检索（谁都问不到）。
下拉显示：是否出现在前台“项目”下拉框；关闭但启用 = 能被自动识别检索到，只是不单独列出（客户资料类建议这样，选产品时会自动带上）。
显示引用源：关闭后回答仍可引用该项目，但前台只显示“[n] 显示名”，不暴露路径和行号。
显示名：下拉框和隐藏引用时展示的名字，留空用项目名。

项目启用下拉显示显示引用源显示名块数

新增项目

填服务器上的目录 → “探测”自动给出要扫描的子目录、别名、当前分支 → 确认后追加写入 sources.toml（和本地手改等价，可 git diff 查看）并自动重新入库。
别名：大家口头怎么叫它，问题里出现别名就只搜这个项目。关联到：本项目是哪些产品的依赖/配套（例如 SDK 被 monitor 使用），选了之后问那些产品时也会带上本项目。
固定分支：填了就用独立检出（git worktree）入库，你本地切分支不影响知识库；留空则跟随工作区。

重新入库

流程：拉取各知识源 → 切块 → 增量向量化（只算改动的块）→ 跑评测集 → 通过卡口才替换线上索引并热加载。
卡口：任何一道以前命中的评测题变成未命中、或 recall@8 下降超过 0.02，就拒绝上线，线上保持旧索引。
新增了更难的评测题导致必然下降时，确认无误后用“强制接受”。

让模型读懂代码（文件概要 + 预测问法）

模型逐个读代码文件，写“这个文件干什么 + 别人可能怎么问”，作为额外索引入库。用户口语提问（不知道类名/函数名）时，靠它命中真正的代码。
按文件内容 hash 缓存：代码没改不重算，新提交只算改动文件。和前台提问共用 GPU，每个文件单独排队，不会卡住前台；量大建议下班后跑。完成后自动重新入库（过卡口才上线）。
